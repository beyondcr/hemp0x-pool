# Hemp0x Core Next Cookie Auth

Use the current Hemp0x Core Next daemon binaries for new pool deployments. The pool can authenticate with `rpcuser` / `rpcpassword`, but cookie auth is preferred because it removes static RPC credentials from the pool config.

## Recommended Layout

Run the pool as a dedicated non-root user, for example `hemp0xpool`, and keep the app outside `/root`:

```bash
/srv/hemp0x-pool
/var/lib/hemp0x-pool
/var/lib/hemp0x-pool/.pm2
```

The daemon may still own the chain data directory. Do not give the pool user direct access to the full daemon data directory unless there is a specific operational reason.

## Daemon Cookie Path

By default, `hemp0xd` creates its RPC auth cookie in the daemon data directory, such as `.cookie` under the Hemp0x data dir. For a non-root pool service, set an explicit cookie path that the pool user can read:

```ini
server=1
rpcbind=127.0.0.1
rpcallowip=127.0.0.1
rpccookiefile=/var/lib/hemp0x-pool/rpc.cookie
```

Do not set `rpcuser` or `rpcpassword` when using cookie auth.

## Cookie Permissions

The cookie is generated by `hemp0xd` at daemon start and may change after daemon restart or system reboot. Ensure the pool user can read the new cookie after each daemon start.

Example systemd drop-in:

```ini
[Service]
ExecStartPost=/bin/bash -lc 'for i in {1..60}; do [ -f /var/lib/hemp0x-pool/rpc.cookie ] && chgrp hemp0xpool /var/lib/hemp0x-pool/rpc.cookie && chmod 640 /var/lib/hemp0x-pool/rpc.cookie && exit 0; sleep 1; done; exit 1'
```

Apply with:

```bash
systemctl daemon-reload
systemctl restart hemp0xd
```

## Pool Config

Configure `config.json` to use cookie auth:

```json
{
  "daemon": {
    "host": "127.0.0.1",
    "port": 42070,
    "useCookieAuth": true,
    "cookiePath": "/var/lib/hemp0x-pool/rpc.cookie"
  }
}
```

Do not include `daemon.user`, `daemon.pass`, or `daemon.password` in production cookie-auth configs.

## Reboot Behavior

The pool startup should be ordered after `hemp0xd.service`. The pool also waits for `getblockcount` and `getwalletinfo` to succeed before starting stratum/web jobs or running payout/consolidation cycles. This avoids noisy failures while the daemon is loading the block index, rewinding blocks, or loading the wallet.

Recommended service ordering:

```ini
After=network.target hemp0xd.service
Wants=hemp0xd.service
```

The pool RPC client re-reads the cookie file after auth failures, so a rotated cookie is picked up without requiring a config change.

## Verification

Run these checks as the pool user:

```bash
test -r /var/lib/hemp0x-pool/rpc.cookie
node scripts/wait-for-rpc-ready.js
```

Expected output:

```text
[rpc-ready] ready height=...
```
