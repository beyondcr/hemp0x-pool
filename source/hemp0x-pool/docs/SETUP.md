# Setup Guide

## Prerequisites

- Node.js 18+ and npm
- Running Hemp0x Core Next `hemp0xd` with RPC enabled
- RPC cookie auth is recommended for production (`rpccookiefile` plus `daemon.useCookieAuth: true`)
- The pool wallet address must belong to the node wallet (or have its private key imported)

## Install

```bash
cd source/hemp0x-pool
npm install
cp config.example.json config.json
```

Edit `config.json` with your settings. Required fields:

| Section | Key | Placeholder | Notes |
|---------|-----|-------------|-------|
| `pool` | `wallet` | `YOUR_POOL_WALLET_ADDRESS` | A valid `R`-prefixed Hemp0x address |
| `pool` | `stratumPort` | `3032` | Must be 1024-65535 |
| `pool` | `webPort` | `8080` | Must be 1024-65535 |
| `daemon` | `host` | `127.0.0.1` | RPC daemon host |
| `daemon` | `port` | `42070` | RPC daemon port |
| `daemon` | `useCookieAuth` | `true` | Recommended for production |
| `daemon` | `cookiePath` | `/var/lib/hemp0x-pool/rpc.cookie` | Cookie generated by `hemp0xd` |

Use placeholder values in the example config. Keep live wallet and RPC settings in your local `config.json`.

For production cookie auth and Hemp0x Core Next daemon setup, see `docs/CORE_NEXT_COOKIE_AUTH.md`.

## Safe First-Run Checks

Before starting the pool, verify:

1. **Run the preflight doctor:**
   ```bash
   npm run doctor
   ```
   This checks config validity, required files, and test status. No RPC calls are made by default.

2. **Config is valid:**
   ```bash
   node -e "const { loadConfig } = require('./config'); console.log(loadConfig());"
   ```
   This will error if a safety gate is violated (e.g., `payout.dryRun` is not `true`).

3. **Daemon is reachable:**
   ```bash
   node scripts/wait-for-rpc-ready.js
   ```

4. **Address formats are valid:**
   ```bash
   node -e "const {isValidAddress} = require('./address'); console.log(isValidAddress('YOUR_POOL_WALLET_ADDRESS'));"
   ```

5. **Tests pass:**
   ```bash
   npm test
   ```

## Running Tests

```bash
npm test
```

Runs all test suites using the Node.js native test runner. Tests use in-memory SQLite databases and mock RPC servers — no live daemon or real wallet needed.

Individual test suites:
```bash
npm run test:config     # Config loading and validation tests
npm run test:rpc        # RPC client tests
npm run test:constants  # Constants and unit conversion tests
```

## Running the Pool

### Stratum + Web Server
```bash
node server.js
```

### Confirmation Tracker
```bash
node confirmation.js
```

### Process Management (PM2)
```bash
pm2 start server.js --name hemp0x-pool
pm2 start confirmation.js --name hemp0x-confirmations
pm2 save
pm2 startup
```

## Runtime Files

Keep live configs, databases, logs, and wallet files on the server only. A fresh install should create its own `config.json`, `pool.db`, and process-manager state.

## Admin Dashboard

After starting the server, access the admin dashboard:

```
http://localhost:8080/admin.html
```

- **Config tab**: Redacted config view, schema metadata, safety gate status
- **Status tab**: Pool uptime, daemon health, active miners, hashrate, payout automation mode, safety gates
- **Payout Plan tab**: Create dry-run payout plans
- **Review tab**: View plan history, record review-only approve/reject
- **Consolidation Plan tab**: Dry-run consolidation planning

### Admin Token (Optional)

To allow remote admin access, set an admin token:

- In `config.json`: `"adminToken": "your-secret-token"`
- Or environment variable: `HEMP0X_POOL_ADMIN_TOKEN=your-secret-token`

Without a token, admin endpoints are localhost-only.
Do not expose the admin interface over direct HTTP. Put remote access behind
HTTPS and a reverse proxy with rate limiting, or keep the dashboard local.

## Payout Worker

Before enabling live payouts, initialize the receiving wallet's accounting
boundary as described in [Payout Accounting Boundaries](PAYOUT_EPOCHS.md).
For a fresh pool, do this before connecting miners. The initialization command
archives existing payout obligations, so review that guide before using it on
an established pool.

The ledger-backed payout worker plans payouts, records each run, broadcasts when live gates are enabled, and confirms broadcasted batches. Start with dry-run planning, then enable live mode only after RPC, wallet, and backup checks pass.

```bash
pm2 start run-live-payout-loop.sh --name hemp0x-pool-payouts
pm2 start run-live-consolidation-loop.sh --name hemp0x-pool-consolidation
pm2 save
```
